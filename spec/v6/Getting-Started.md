# Getting Started

Kristal v6 starts with a small question: **what do you need to remember in a structured, traceable form?**

## 1. Identify stable referents

Give durable identities to the things your assertions are about: concepts, rules, components, taxa, recipes, institutions, symptoms, documents, processes, etc.

## 2. Write atomic assertions

Use subject → predicate → object relationships small enough that evidence, applicability, measurement or disagreement can differ independently.

## 3. Add the right context

- `coordinates` for domain geometry;
- `applicability` for the conditions under which the assertion applies;
- `record_role` when the functional role matters.

## 4. Add valuations only when meaningful

Choose a dimension and a value semantics. Do not force structural assertions onto a metric; `not_applicable` is legitimate.

## 5. Preserve evidence and provenance

Record where the assertion came from and what supports it.

## 6. Keep validation and recognition separate

A source does not automatically validate a claim. Validation does not automatically confer universal authority.

## 7. Add actionability only when policy is explicit

If the organization knows when work can be automated vs when a human is required, represent that boundary. Do not infer it from a high valuation.

## 8. Derive views

Build timelines, pathways, diagnostic views, indexes, readers or consumer projections from the canonical state rather than maintaining parallel truth stores.

See [Quickstart](Quickstart.md) for a minimal example.
