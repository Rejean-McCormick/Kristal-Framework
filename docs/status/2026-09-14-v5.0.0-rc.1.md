## Executive status

Kristal Framework 5.0.0-rc.1 is the first release candidate that treats the v5 corpus as a **pinnable, machine-verifiable contract release** rather than documentation alone.

The epistemic model remains Kristal v5. This stabilization work adds release identity, deterministic manifests, conformance gates, release packaging, and Git tagging guidance without moving Interaction Kernel semantics into Kristal Core.

The release candidate is suitable for downstream integration testing by Da'at, kOA, Konnaxion, and Orgo. A downstream production lock SHOULD additionally record the full Git commit SHA resolved from the signed release tag.

## Release identity model

A Kristal release is identified by the tuple:

```text
semantic version
+ signed Git tag
+ resolved immutable Git commit SHA
+ contract_set_digest
+ schema_set_digest
+ canonicalization profile/version
```

The repository intentionally does **not** self-embed its own Git commit SHA inside `kristal-release.json`. The signed tag resolves to the immutable commit after the release commit exists. Consumers record that resolved SHA in their own lock file.

## Required downstream lock

A high-assurance downstream integration SHOULD record at least:

```json
{
  "version": "5.0.0-rc.1",
  "git_tag": "v5.0.0-rc.1",
  "git_commit": "<full SHA resolved from tag>",
  "contract_set_digest": "sha256:3cac653f423395ee859f815681a293a80e26808d8f39a686655cd40f17042599",
  "schema_set_digest": "sha256:7a94a1e8a91d5c5267b73b7f1e98977faa548324bc937bb491cd08d49fdc8c92",
  "canonicalization_profile": "kristal.v5:jcs-rfc8785",
  "canonicalization_version": "1"
}
```

Floating dependencies such as `main`, `latest`, or `5.x` are not valid high-assurance release locks.

## Known release-candidate limitations

1. `v5.0.0-rc.1` has not yet been created in the authoritative Git repository represented by this exported snapshot.
2. The full immutable Git commit SHA therefore cannot yet be recorded by downstream consumers.
3. `mkdocs build --strict` should be executed in the authoritative Git/CI environment with the declared documentation dependencies installed. The repository-level local link and navigation validator passes.
4. The release remains an RC until the contract set is intentionally frozen and the final stable release gates are executed for `v5.0.0`.

## Promotion criteria for v5.0.0

Promote this RC to stable only when all of the following are true:

- the RC changes are committed in the authoritative repository;
- the `v5.0.0-rc.1` tag is created and verified;
- CI passes from the tagged commit;
- Da'at integration tests pass against the pinned RC;
- no incompatible contract defect is found during RC validation;
- `VERSION`, `kristal-release.json`, and `CHANGELOG.md` are updated to `5.0.0`;
- manifests are rebuilt and validated;
- the final `v5.0.0` tag is signed/annotated and pushed.
