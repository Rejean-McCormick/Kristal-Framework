## Executive status

Kristal Framework 5.0.0-rc.1 stabilizes the v5 corpus as a pinnable Git release while keeping the release machinery deliberately small.

The epistemic model remains Kristal v5. Release identity is based on **semantic version + Git tag + resolved commit SHA**. The repository does not maintain a perfect inventory of every file and does not add a second content-hash identity system on top of Git.

`contract-set.manifest.json` is a curated map of the public normative, profile, conformance, and informative surfaces. It exists so integrators know what constitutes the public Kristal contract; it is not a generated checksum catalog.

## Release identity model

A Kristal framework release is pinned by:

```text
semantic version
+ Git tag
+ resolved immutable Git commit SHA
```

The tag names the release. The commit SHA identifies the exact repository tree. This is sufficient for Da'at, kOA, Konnaxion, Orgo, and IK to pin the framework without duplicating Git with a second repository-wide hashing system.

Kristal's own SHA-256/JCS rules remain normative where they belong: **artifact/content identity inside the Kristal protocol**.

## Downstream lock

A downstream integration SHOULD record:

```json
{
  "version": "5.0.0-rc.1",
  "git_tag": "v5.0.0-rc.1",
  "git_commit": "<full SHA resolved from tag>",
  "canonicalization_profile": "kristal.v5:jcs-rfc8785"
}
```

Floating dependencies such as `main`, `latest`, or `5.x` are not valid release locks.

## Known release-candidate limitations

1. `v5.0.0-rc.1` still needs to be created in the authoritative Git repository.
2. The full immutable Git commit SHA cannot be recorded by downstream consumers until the release commit/tag exists.
3. `mkdocs build --strict` should run in the authoritative Git/CI environment with the declared documentation dependencies installed.
4. The release remains an RC until Da'at integration tests pass and no incompatible contract defect is found.

## Promotion criteria for v5.0.0

Promote this RC to stable when:

- the RC changes are committed in the authoritative repository;
- the `v5.0.0-rc.1` annotated (or optionally signed) tag exists;
- CI passes from the tagged commit;
- Da'at integration tests pass against the pinned RC;
- no incompatible contract defect is found;
- `VERSION`, `kristal-release.json`, `contract-set.manifest.json`, and `CHANGELOG.md` are updated to `5.0.0`;
- the final `v5.0.0` tag is created and pushed.
