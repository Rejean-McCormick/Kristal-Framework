## Why rc.2 exists

The published `v5.0.0-rc.1` baseline is immutable. Post-rc.1 validation exposed release-tooling drift and several cross-document identity/lifecycle inconsistencies. Because the corrections touch normative release, reproducibility, schema, and conformance surfaces, they require a new release-candidate identity rather than reuse of rc.1.

## Corrections in this candidate

- Retire `schema-set.manifest.json` and `tools/build_manifests.py`; Git tag + resolved commit SHA remain the byte-level framework release identity.
- Record both `canonicalization_profile` and `canonicalization_version` in release metadata and consumer locks.
- Enforce JSON Schema `format` validation for examples and Runtime Pack vectors.
- Build source release archives from Git-tracked files only; untracked diagnostics cannot contaminate release bytes.
- Exclude `CODE_SNAPSHOT_MANIFEST.md` from framework release archives.
- Define `kristal.v5:exchange-id-core@1` as the stable Exchange payload identity boundary and explicitly separate it from compiler/build-run identity.
- Require authority-recognition evidence for `reference_exchange` and align recognized/reference lifecycle semantics.
- Normalize Runtime Pack format version examples/vectors to `5.0.0`; the Runtime Pack format version is not the framework RC version.
- Use `artifact_type = "runtime_pack_manifest"` consistently for the distributed Runtime Pack manifest.
- Run the framework validation matrix on Linux and Windows in CI.

## Claims not yet established

A green rc.2 framework gate does **not** by itself establish production qualification. The following remain separate evidence requirements:

- external compiler/verifier implementation conformance for EX-1..EX-4;
- complete Runtime Pack implementation conformance for RP-1..RP-6;
- cryptographic signature/trust fail-closed vectors using real keys/signatures;
- convergence of independent implementations;
- Da’at + Interaction Kernel + producer/consumer end-to-end integration;
- operational load, retry, crash-recovery, rollback, and observability qualification.
